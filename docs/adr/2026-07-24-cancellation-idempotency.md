# ADR: 결제 취소 API 멱등성

- 상태: Accepted
- 날짜: 2026-07-24
- 범위: `POST /api/v1/payments/{paymentId}/cancel`

## 배경

취소 gateway가 추가된 뒤에도 취소 API에는 요청 멱등키가 없었습니다. PG 취소가 성공한 뒤 클라이언트가 응답을 받지 못해 같은 취소를 재요청하면, 내부 상태와 외부 호출의 중복을 명확히 판단할 기준이 필요합니다.

## 결정

- 취소 API는 승인 API와 동일하게 `Idempotency-Key` 헤더를 필수로 받습니다.
- 취소 성공 시 `payments.cancellation_idempotency_key`를 저장합니다.
- 이미 취소된 결제에 같은 key가 들어오면 기존 취소 응답을 반환하고 gateway를 다시 호출하지 않습니다.
- 이미 취소된 결제에 다른 key가 들어오면 `409 INVALID_PAYMENT_STATUS_TRANSITION`을 반환합니다.
- PG 취소가 거절되면 key를 저장하거나 내부 상태를 변경하지 않습니다.
- 웹훅으로 취소 보정하는 경우 transmission ID를 취소 처리 식별자로 저장합니다.

## 대안과 선택 이유

1. 취소 key를 저장하지 않고 상태만 확인하는 방법
   - 같은 요청인지 다른 요청인지 구분할 수 없어 재시도 응답의 일관성이 떨어집니다.
2. 모든 취소 재요청을 무조건 `409`로 처리하는 방법
   - 클라이언트가 응답 유실 후 안전하게 결과를 재확인하기 어렵습니다.
3. 성공 key를 저장하고 같은 key만 기존 응답으로 처리하는 방법
   - 승인 API와 같은 멱등성 계약을 유지하면서 외부 PG 중복 호출을 막을 수 있어 선택했습니다.

## 제한과 다음 단계

- 현재 취소는 전액 취소만 지원하며, 부분 취소를 도입할 때는 취소 금액별 operation key와 취소 이력 모델을 별도로 설계해야 합니다.
- 운영 환경에서는 idempotency key의 요청 주체와 감사 로그를 함께 보존하는 정책을 검토합니다.
