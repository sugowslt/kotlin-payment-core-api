# ADR: 부분 취소와 취소 이력

- 상태: Accepted
- 날짜: 2026-07-24
- 범위: 승인된 결제의 전액·부분 취소

## 배경

전액 취소만 결제 상태에 저장하면 부분 취소가 여러 번 발생했을 때 남은 환불 가능 금액과 각 PG 취소 요청을 추적하기 어렵습니다. Toss 취소 API도 `cancelAmount`로 부분 취소를 지원하므로 내부에도 금액 누적과 이력 경계가 필요합니다.

## 결정

- `Payment.canceledAmount`에 누적 취소 금액을 저장합니다.
- `payment_cancellations`에 취소 key, 금액, 사유, PG 취소 식별자, 생성 시각을 저장합니다.
- 남은 금액보다 큰 취소나 0 이하 금액은 `400 INVALID_PAYMENT_CANCELLATION`으로 거절합니다.
- 누적 취소 금액이 결제 금액과 같을 때만 결제 상태를 `CANCELED`로 바꾸고, 부분 취소 중에는 `APPROVED`를 유지합니다.
- 취소 idempotency key는 이력 테이블에서 재사용 여부를 판단합니다.
- 웹훅으로 최종 취소를 보정할 때도 남은 금액을 이력으로 기록합니다.

## 대안과 선택 이유

1. Payment에 마지막 취소 금액만 저장하는 방법
   - 여러 번의 부분 취소와 PG transaction key를 잃어버립니다.
2. 취소 금액을 상태 문자열에만 포함하는 방법
   - 금액 정합성 검증과 운영 조회가 어렵습니다.
3. 누적 금액과 별도 이력 테이블을 함께 저장하는 방법
   - 현재 잔액 판단은 빠르게 유지하면서, 재처리·감사·PG 응답 추적을 분리할 수 있어 선택했습니다.

## 제한과 다음 단계

- 가상계좌 환불 계좌 정보와 면세 금액 등 결제수단별 취소 필드는 아직 지원하지 않습니다.
- 운영에서는 취소 이력을 조회하는 별도 운영 화면과 감사 로그를 추가 검토합니다.
